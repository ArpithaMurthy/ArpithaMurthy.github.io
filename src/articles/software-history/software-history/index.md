# The Story of Software: From Mechanical Rules to Machine Intelligence

Software did not appear all at once. It grew out of a long human wish: make a machine follow instructions, then let more people give it instructions, and eventually ask it to produce answers we did not specify line by line. This series follows that change—from gears and punched cards to desktop apps, the web, phones, cloud services, and generative AI.

The connecting question is: **where does the instruction live, and who gets to use it?** In Babbage's time, instructions were an ambitious mechanical design. Later they were wires, switches, code in memory, programs on a personal computer, services reached through a browser, apps carried in a pocket, and models running in data centers.

## Follow the story

1. [Before software had a name: Babbage, Lovelace, and the programmable machine](/articles/mechanical-instructions/) — What changes when a machine can follow a general set of instructions instead of repeating one calculation?
2. [When the machine learned to follow a program](/articles/the-machine-gets-a-memory/) — How stored programs and programming languages helped separate software from the hardware.
3. [A computer on your desk: operating systems and desktop apps](/articles/a-computer-on-your-desk/) — How the computer moved from institutions and hobbyists into homes and offices.
4. [The web puts software within reach](/articles/the-web-in-the-browser/) — How open networks and browsers turned documents into interactive services.
5. [A computer in your pocket: the mobile-app shift](/articles/apps-in-your-pocket/) — How touchscreens, sensors, and app stores made software personal and always nearby.
6. [Software becomes a service: the cloud era](/articles/software-from-the-cloud/) — How the computer behind the app moved into data centers and became a service.
7. [When software began to generate: AI enters everyday apps](/articles/software-that-can-create/) — What changes when people can ask software for an output instead of choosing from a fixed set of commands?

Each episode is written to make sense on its own. Reading them in order reveals the larger shift: each generation makes computing easier to reach, while moving more of the complexity somewhere else. This is a first, selective arc—not a complete history of software or the software industry.

## A story, not a list of inventions

This is not a claim that one inventor or product single-handedly created modern computing. Each change came from many people, research groups, businesses, standards, and users. Dates mark useful turning points, not a single start or finish. The episodes are original explanations based on historical research; further-reading links point to sources for readers who want more detail.

The story is also a companion to existing histories, not a replacement for them. The [Computer History Museum timeline](https://www.computerhistory.org/timeline/) and the [W3C's history of the Web](https://www.w3.org/History.html) are useful places to explore further. Each episode includes a short reading list so you can follow the source trail. Important topics—including the birth of the software industry, Unix and open-source software, the internet before the Web, and the rise of databases and networked business software—deserve their own episodes in a fuller history.
