# When the Machine Learned to Follow a Program

The earliest electronic computers could fill a room, but changing what they did could be painfully physical. On some machines, operators rearranged cables, switches, or plugboards. The computer's behavior was tied closely to its hardware and to the specialists who knew how to configure it.

The next big shift was not simply making the machine faster. It was making the instructions easier to change.

## Put the program where the machine can find it

The stored-program idea placed instructions in the computer's memory alongside the data they operated on. Instead of rebuilding the machine for each task, people could load a different program. The machine could fetch an instruction, carry it out, and continue through a sequence.

This sounds ordinary now, but it changed what a computer was. It became a general-purpose machine whose behavior could be changed through software. The distinction between a program and a machine was still incomplete: computers were expensive, scarce, and operated by institutions, while writing machine instructions required deep knowledge of the hardware.

## Teach people a more practical language

Programmers needed ways to express work without writing every low-level operation themselves. Grace Hopper's A-0 system, completed in 1952, helped translate symbolic instructions into machine operations and is commonly described as an early compiler. FORTRAN, developed by an IBM team led by John Backus and released in 1957, made scientific programming more accessible. COBOL followed as a language aimed at business data processing.

The shift was also organizational. Programs could be written, tested, maintained, and sold as valuable work. Software was becoming more than a hidden step in operating a machine; it was a growing part of the computing business.

## The operating system makes a shared machine usable

As organizations asked more people to use expensive computers, operating systems began managing jobs, memory, input and output, and access to the machine. Time-sharing systems let multiple people interact with one computer through terminals rather than waiting for a single job to finish.

Users still did not own a computer. They borrowed time on one. But the path from an idea to a running program was changing: the hardware could be shared, and software could manage the sharing.

## What changed for people?

Scientists, governments, and businesses could ask computers to do different kinds of work without constructing a new machine each time. Programmers gained languages that expressed intent more clearly. Yet computers remained centralized resources, and most people encountered their results indirectly.
